Chart of accounts

Eight types, and where each one surfaces

One ambiguity to resolve with the evaluator, not guess at

The mockup's account-type dropdown lists five options while the balance-sheet notes read like sub-types (Asset-Bank, Asset-Debtors). Eight flat types satisfies both readings and keeps the reports simple. If it turns out to mean a two-level taxonomy, only the grouping query changes — no table does.

The ledger

Two tables, and the constraints that make them true

journal_entries entry_number unique JE/2026/00001 · own sequence, independent of any document journal_id FK entry_date · reference state enum DRAFT | POSTED | REVERSED source_type text customer_invoice | vendor_bill | payment | manual source_id uuid reversal_of_id FK set on the reversing entry posted_at · posted_by_id UNIQUE (source_type, source_id) WHERE state != 'REVERSED' └ the database-level guard against double posting journal_lines entry_id · account_id · analytic_account_id? · partner_id? · label debit Numeric(14,2) default 0 credit Numeric(14,2) default 0 CHECK (debit >= 0 AND credit >= 0) no negative postings CHECK (NOT (debit > 0 AND credit > 0)) a line is one-sided CHECK (debit > 0 OR credit > 0) no empty lines
Why the balance rule is not a CHECK constraint

A CHECK cannot see sibling rows, so Σ debit = Σ credit is asserted in the posting service — but inside the same transaction as the insert. A failure rolls the whole posting back, so it is never possible to commit an unbalanced entry. The three CHECKs above catch everything a single row can get wrong; the service catches the one thing it can't.

Budget

The revision chain

Confirmed budgets are never edited. Revising one creates a successor and links both directions — the same immutability instinct as the ledger, applied to planning.

Stored per budget line

  • analytic_account_id
  • committed_amount — the plan

That is all. Everything else is derived, so nothing can go stale.

Computed on read

  • Achieved — Σ matching document lines in the period
  • Achieved % — achieved ÷ committed × 100
  • To achieve — committed − achieved

Clicking the achieved figure opens the documents behind it.

Standing rules

Applied to every table without exception

  • Money is Numeric(12,2). Never Float — drift shows up on screen.
  • Dates are DateTime(timezone=True), always UTC. Mixing date.today() with datetime.now(UTC) broke three tests on every IST machine last round.
  • Status columns are Python enums with native_enum=False.
  • Unique on every document number, account code, contact email, and the payment idempotency key.
  • CHECK for every numeric rule — quantity > 0, unit_price >= 0, amount > 0.
  • Index every column filtered or sorted on: status, all foreign keys, all dates.
  • Archive, never delete. Archived accounts reject new postings.
