# CARD C — Frontend #2 · Pitch · Overview · Floater

> **Branch:** `feature/dashboard` (and wherever you're helping) · **Merges:** → `dev` (via Card D review)
> **Keep open:** `../09_DEMO_AND_PRESENTATION.md` from 18:00 onward

## Your mission in one line
**Own the story the judges hear — and be the second pair of hands wherever the team is slowest.**

This is the widest card. You are half builder, half narrator, and you're the only person whose
job includes *looking up from the code*.

## What you own

### 1. Dashboard, analytics, and reports (your build lane)
The KPI screen, charts, and any export the PS asks for. These are high-visual-impact,
low-coupling screens — perfect for a second frontend person because they don't collide with
Card A's CRUD work.

### 2. The narrative (your differentiating lane)
- **The demo script** — written by 18:00, rehearsed by 22:00, not improvised at 09:00
- **The video** — recorded, uploaded, incognito-tested, submitted by 10:30
- **The 13:00 live presentation** — you drive it
- **The README** — kept truthful continuously, re-tested from a fresh clone before submission

### 3. Overview (your quiet lane)
You are the person who notices that nobody has tested the login flow in six hours. Every couple
of hours, step back and ask:
- Does the demo path still work **end to end**, right now?
- Is anything in the PS's mandatory list still unbuilt?
- Is anyone silently stuck?
- Are all four commit streams still active?

### 4. Floater (your overflow lane)
**Backend is our bottleneck this round.** When Card B is deep in the rule engine, you take:
seed data, analytics SQL, CSV export. Coordinate so you're not editing the same files.

## Priority order when everything competes
1. The demo path works
2. The video ships on time
3. Your own dashboard screens
4. Overflow help

**If you must drop something, drop your own screens — not the video.** A missing chart costs a
few points; a missing video submission is a zero.

## Hard rules
- **The video is a hard deadline with no slack.** Start recording at 10:00, not 10:20.
- Record the **browser, not the IDE** — they asked for functional flow, not a code tour.
- Never demo a path you haven't run in the last hour.
- Prep answers to: *"what was hardest?"*, *"what would you do with another week?"*,
  *"why this tech choice?"* — real answers, not modesty.

## Definition of done
Dashboard screens shipped · demo script written and rehearsed · video submitted with margin ·
README truthful and re-tested from scratch · live presentation delivered with all four able to
answer for their own area.
